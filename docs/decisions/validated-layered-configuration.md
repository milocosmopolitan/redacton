# Validate layered configuration before activation

The terminal and any independently qualified Desktop renderer share pure TypeScript settings, controllers, snapshots and safe views. SDK capabilities remain in host registration; engine compilation, parsing and privileged persistence remain in the separate pinned helper.

Approved personal, project and session layers explicitly replace the entire custom-rule list in that order. Built-in credential redaction and private-key blocking are invariant. Custom actions are redact/block only; no user rule disables a detector. Pinned beta.14 defaults custom matches to warn, so attaching a ruleset without the explicit protection callback is invalid. Its names detector has no per-rule identity; reject mixed names actions instead of inferring provenance from sensitive text.

Local forms follow edit → core validation → synthetic preview → explicit apply. Opaque monotonic active revisions and durable scope revisions detect stale callbacks, saves and undo. Operations capture exact immutable policy/configuration at start. Invalid candidates and failed writes leave the previous active configuration unchanged.

Project configuration is declarative untrusted data until exact-revision local approval. Trust and session drafts do not survive a session reset. Privileged writes validate before atomic replacement under a lock and compare the durable revision. Persist only approved definitions, never OFF, inputs or recent history. Configuration response bodies may reach the local form, never a model message or diagnostics.

Status reads cached state only, with observation time; it performs no helper call, settings initialization or health check. Preview establishes a synthetic result, not detection accuracy. Desktop protection and three-user/seven-day usability evidence remain independently gated. Preserve the existing conditional layered-host assurance and storage exclusions.
