# Actual terminal UI qualification

Claude Code 2.1.294, macOS ARM64. An isolated PTY ran the repository plugin with synthetic credentials and no model requests. No real user auth/config/transcripts were inspected. Test processes and temporary configuration were removed. No raw screen or screenshot is committed.

## Normal terminal

The 40-row, 140-column normal terminal was interpreted with task-local `pyte@0.8.2`. Checks used its current decoded screen, not searches for a warning somewhere in the accumulated byte stream.

- `/redactoff` executed and displayed the immediate warning.
- The OFF warning appeared above the input prompt and remained on the decoded screen after a synthetic draft was typed.
- The draft was cleared; `/redacton` executed and reported Protect ready. The OFF warning disappeared from the current screen.
- A second `/redactoff` restored the warning above the input prompt.
- The qualification-only companion command `/ui-tool-probe` called the actual core Bash tool with a harmless synthetic printf while the product was OFF. Its fixed success response proved completion, and the OFF warning remained on the current decoded screen afterward. The companion is not shipped with the product and no model request was required.

All recorded normal-terminal checks passed. See [fixed observations](ui-report.json). `childExitCode: null` means the interactive child was still running when checks completed; the harness then killed its test-owned process group and removed its temporary configuration.

Reproduction requires Python and a temporary installation of `pyte==0.8.2`. Set `PYTHONPATH` to that task-local target and run `python3 qualification/normal-ui.py` from the repository root. Remove the target afterward; pyte is not a product dependency. The shell entrypoint uses RTK, while the internal argv-only Claude child preserves its PTY because RTK's capture would force print mode.

The normal trust menu defaults to No, exit. Wait for the input handler, use DownArrow to choose Yes, then send Enter separately. The synthetic custom API-key menu is answered independently. The probe uses a one-second readiness wait and 200 ms between selection/input and Enter. This avoids mistaking unanswered onboarding for a UI failure.

## Screen-reader mode

`python3 qualification/terminal-ui-alternative.py` independently verified immediate warning output and the OFF line directly before the next prompt, followed by a typed synthetic draft. This renderer emits sequential text, so absence of a warning redraw during typing is expected and was recorded as false rather than claimed as a redraw pass. It uses yes/no onboarding input instead of normal arrow-key selection.

## Coverage limits

The checks prove the observed command/typing and actual core-tool interactions at one terminal size on this host. They do not qualify Desktop, other platforms, every terminal size, or arbitrary scroll state. The tool was requested through a qualification companion's local SDK call rather than generated by a model; this distinction remains explicit.

SDK render-tree acceptance and actual terminal evidence remain separate. For API/status fallback facts and official references see [UI research](ui-research.md). Protection interception and host transcript/storage qualification are separate from these warning checks.
